The Quantum Challenge

A 5-step journey from the quantum threat to the AI-powered routing solution. Use the controls to step through manually, or let it play automatically.

🚨 Threat

The Quantum Break

In 1994, Peter Shor proved that a sufficiently powerful quantum computer running his algorithm could break RSA and ECC in hours — the algorithms protecting every HTTPS session today.

Proof: Gartner forecasts quantum computers will defeat RSA and ECC as early as 2029. Gidney & Ekerå (2019) estimated RSA-2048 could be factored in about 8 hours with 20 million noisy qubits; Gidney (2025) cut that to under 1 million qubits in under a week.
🛡️ NIST Response

The Lattice Defense

To counter the threat, NIST standardized new lattice-based algorithms: ML-KEM for key exchange and ML-DSA for digital signatures. These resist quantum attacks.

Proof: On August 13, 2024, NIST officially released FIPS 203 (ML-KEM) and FIPS 204 (ML-DSA) as the global standards for post-quantum cryptography.
🐢 Performance Cost

Secure, But Heavy

PQC is mathematically secure, but computationally expensive. In a cluster of servers, hardware variance means some nodes are far slower than others. Signature algorithms like ML-DSA are particularly heavy.

Proof: Our own benchmarks show ML-DSA-65 has a P95 latency of 679µs, while ML-KEM-512 is only 89µs. Blind routing guarantees wasted time on slow nodes.
⚖️ Routing Bottleneck

Round Robin Fails

Traditional Round-Robin load balancers blindly cycle through every node, regardless of its speed. In a heterogeneous cluster, this drags average latency up and creates bottlenecks.

Proof: Research on heterogeneous Kubernetes clusters shows traditional scheduling strategies fail to optimize latency-sensitive applications, leading to SLO violations.
🧠 AI Solution

Q-Learning Router

We built a Q-Learning agent. It explores the cluster, measures node latencies, and updates its Q-Table. As ε decays from 0.30 to 0.05, it increasingly exploits the fastest node, cutting latency dramatically.

Proof: By balancing exploration and exploitation, our AI load balancer reduces mean latency by 76% compared to Round Robin. Reinforcement learning schedulers have been shown to reduce latency significantly even in complex Kubernetes environments.
The pipeline

Three steps. One adaptive router.

Every request flows through a stateless balancer that consults the agent's learned Q-table before dispatching to a worker node.

01

Request arrives

A client sends a PQC algorithm request. The balancer maps the algorithm to a state (algo_type, security_level).

02

Agent selects node

The Q-learning agent evaluates the Q-table for that state and picks the node with the maximum value, factoring in a 5% chance to explore (ε = 0.05).

03

Reward & update

After measuring latency, the Q-value is updated with the standard formula. The next request benefits from what the agent just learned.

The math

Q-learning, kept simple.

The update rule

Every request makes the agent a little smarter.

The agent learns from the reward r = 1000 / (latency + 1). Faster responses yield higher rewards, so the Q-value for the winning node climbs faster than the others. We use ε-Greedy (ε=0.30 → 0.05), so it mostly exploits the best node but occasionally explores others.

Q(s,a) ← Q(s,a) + α · [ r − Q(s,a) ]
α = 0.5 · r = 1000 / (latency + 1)Example: Q = 500, latency = 10 ms → r = 90.9
Q ← 500 + 0.5 × (90.9 − 500) = 295.5

Questions

Things people ask.

What is Post-Quantum Cryptography?
PQC refers to cryptographic algorithms that resist attacks from quantum computers. RSA and ECC — the algorithms powering HTTPS today — will be breakable by large-scale quantum machines. ML-KEM (based on Kyber) and ML-DSA (based on Dilithium) are the NIST-standardized replacements.
Why Q-Learning instead of Round Robin?
Round Robin assumes all nodes are equal. In a heterogeneous cluster, some nodes are far slower than others. Round Robin keeps them all in rotation, dragging average latency up. Q-learning learns the fastest node and keeps sending traffic there.
Why use ε-Greedy (ε = 0.30 → 0.05)?
The agent needs to explore the cluster initially to find the fastest node, so ε starts at 0.30. Over time, it decays to 0.05 to focus on exploitation. This 5% minimum ensures that if a node becomes slow or a new node is added, the agent can still adapt. It is a known trade-off: the 5% exploration is why mean latency improves by 76%, but P95 tail latency improves slightly less (10-20%).
How is this deployed in production?
The entire stack is containerized using Docker and Docker Compose. The balancer and worker nodes are deployed as separate microservices. In a real production environment, this would be orchestrated via Kubernetes, with the Q-Learning agent persisting its Q-table to a shared Redis instance to survive pod restarts.
